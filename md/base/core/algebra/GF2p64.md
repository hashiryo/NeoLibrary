$\mathbb{F}_{2^{64}} = \mathrm{GF}(2)[x]/(x^{64} + x^4 + x^3 + x + 1)$ の元です。値は 64 bit の整数で、bit $i$ が多項式の $x^i$ の係数です。和と差はどちらも XOR で、積は標数 2 の多項式の積を $x^{64} + x^4 + x^3 + x + 1$ で割った余りです。この多項式は既約で、剰余環の元 $x$ は $\mathbb{F}_{2^{64}}^\times$ の生成元です。

```cpp
class GF2p64;
GF2p64(unsigned long long y = 0);                 // 既定は 0。64 bit のどの値も体の元
static GF2p64 from_nimber(unsigned long long n);  // nimber の値 n から作る
static GF2p64 generator();                        // 多項式の x (値の 2)。log() の底
auto operator<=>(const GF2p64&) const = default;  // == も使える
GF2p64& operator+=(GF2p64 r);                     // -=、*=、/= と二項の + - * / もある
GF2p64 square() const;                            // x^2
GF2p64 sqrt() const;                              // 2 乗すると x になる元
GF2p64 inv() const;                               // 逆元。0 で呼ぶと assert
GF2p64 pow(unsigned long long e) const;           // x^e。0^0 = 1
unsigned long long log() const;                   // generator()^k = x となる k
unsigned long long log(GF2p64 base) const;        // base^k = x となる最小の k。なければ 2^64 - 1
unsigned long long ord() const;                   // x^k = 1 となる最小の k ≥ 1。0 で呼ぶと assert
unsigned long long to_nimber() const;             // nimber の値へ
explicit operator unsigned long long() const;     // 64 bit の値
explicit operator bool() const;                   // 0 でないか
friend std::ostream& operator<<(std::ostream& os, const GF2p64& r);
friend std::istream& operator>>(std::istream& is, GF2p64& r);
```

`GF2p64(y)` は `y` の bit $i$ を多項式の $x^i$ の係数として、剰余を取らずにそのまま値にします。整数からは暗黙に作れます。`+` と `-` はどちらも XOR で、`*` と `/` は体の演算です。`/` は右辺の `inv()` を掛けます。0 で割ると `inv()` の assert で止まります。

`square()` は `x * x` と同じ値ですが、clmul を使わない速い道で求めます。`sqrt()` は $x^{2^{63}}$ を返します。$\mathbb{F}_{2^{64}}$ では 2 乗が全単射なので、平方根はどの元にも 1 つだけあります。

`pow(e)` は $x^e$ を、指数を 4 bit ずつに切って、$x^0, \ldots, x^{15}$ の表と Frobenius の線形写像で求めます。指数の大きさによらず掛け算は 28 回で、$0^0 = 1$ です。

`x.log()` は `generator()` を底とする離散対数で、$0 \le k < 2^{64} - 1$ の $k$ を返します。`ord()` は $x^k = 1$ となる最小の $k \ge 1$ で、$2^{64} - 1 = 3 \cdot 5 \cdot 17 \cdot 257 \cdot 641 \cdot 65537 \cdot 6700417$ の約数です。`x.log()` と `ord()` は 0 で呼ぶと assert で止まります。

`x.log(base)` は `base.pow(k) == x` となる最小の $k$ を返し、解がなければ $2^{64} - 1$ を返します。`pow` の $0^0 = 1$ に合わせて、底が 0 のときは $\log_0 1 = 0$、$\log_0 0 = 1$ です。底が 0 で値が 0 でも 1 でもないとき、底が 1 で値が 1 でないとき、底が 0 でなく値が 0 のときは解がありません。

$\mathbb{F}_{2^{64}}$ は nimber の体と同型です。`from_nimber(n)` は nimber の値 `n` をこの体の元にし、`to_nimber()` はその逆です。nimber の値 $a, b$ の積は、`GF2p64::from_nimber(a) * GF2p64::from_nimber(b)` の `to_nimber()` で得られます。たとえば `from_nimber(2) * from_nimber(2)` は `from_nimber(3)` と同じ値です。

比較 (`<=>` と `==`) は 64 bit の値の大小と一致で行います。ストリームの入出力は 10 進の 64 bit の値です。ヘッダは C++20 以上が要ります。x86-64 では PCLMULQDQ を使い、x86-64 以外では SIMDe (`simde/x86/avx2.h` と `simde/x86/clmul.h`) が要ります。SIMDe を使うときは `SIMDE_ENABLE_NATIVE_ALIASES` を定義してください。

## 中身

値は多項式の係数を詰めた 64 bit です。積は、clmul (x86-64 では PCLMULQDQ、ほかの環境では SIMDe) で 128 bit の積を求め、上の 64 bit を $x^{64} = x^4 + x^3 + x + 1$ の関係で下へ畳みます。上位 4 bit のあふれは 8 個の表で引きます。

2 乗は、標数 2 では係数の 2 乗が係数のままなので、bit を 1 個飛ばしに広げる操作になります。これを pshufb の表で行い、積と同じ関係で畳みます。2 lane の版 (`sq2`) もあります。

逆元は、$a$ のノルムを $\mathbb{F}_{2^{16}}$ まで落として、その逆元を 128 KiB の表で引き、$\mathbb{F}_{2^{16}}$ から $\mathbb{F}_{2^{64}}$ への埋め込みの線形写像で戻します。

Frobenius の写像 $x \mapsto x^{2^k}$ は $\mathbb{F}_2$ 上の線形写像なので、8 bit ずつの表 (1 枚 16 KiB) で引けます。`pow` はこの表を 4 枚使い、`sqrt` は $k = 63$ の 1 枚を使います。

$2^{64} - 1$ は平方因子を持たないので、`log` と `ord` は素因数ごとの成分に分けて求めます。素因数は $3 \cdot 5 \cdot 17 \cdot 257 \cdot 641 \cdot 65537 \cdot 6700417$ です。各素数での判定と対数は、元をノルムで部分体へ落として表を引く形です。6700417 の成分は、2 の冪を掛けると移り合う元の類 (軌道) を 1 MB の表に持ち、そこから引きます。`log(base)` は素数ごとの対数を CRT で組んでから、底の位数で割った余りを取ります。

`log`、`log(base)`、`ord` の表はクラステンプレート `Log<D>` の静的メンバに置き、その関数を使う翻訳単位でだけ実体化されます。表はすべて constexpr でコンパイル時に作るので、実行時の初期化はありません。主な表の大きさは、逆元が 128 KiB、`pow` の Frobenius が 64 KiB、`sqrt` が 16 KiB、`log(base)` の組が 2 MB 前後、`ord` が 224 KiB ほどです。

`pow`、`inv`、`log`、`log(base)` は、呼ばれるたびに `__builtin_cpu_supports("vpclmulqdq")` で 2 lane の道を選びます。使えなければ 128 bit の clmul を 2 回に分けます。
