無向グラフの全点対の最小カットを、同じ頂点の上の重み付きの木 1 本にまとめます。

```cpp
template <class Cap> struct GomoryHuTree {
  std::vector<int> parent;  // 根は 0 で parent[0] = -1
  std::vector<Cap> weight;  // weight[v] は辺 (v, parent[v]) の重み
  std::vector<int> depth;   // 根からの辺の数
  Cap min_cut(int u, int v) const;
};
template <class Cap> GomoryHuTree<Cap> gomory_hu(int n, const std::vector<std::tuple<int, int, Cap>>& edges);
```

頂点 n 個と、容量付きの無向辺 {u, v, c} の列を受けます。`Cap` は 64 bit までの整数の型で、容量は 0 以上です。多重辺、自己ループ (使いません)、容量 0 の辺があってもかまいません。連結でなくてもよく、つながっていない 2 頂点の最小カットは 0 です。各頂点に接する辺の容量の和が `Cap` と `long long` に収まる必要があります (最小カットの値はこれを超えません)。

返す木は、頂点 0 を根とし、各頂点の親を `parent` に、辺 (v, parent[v]) の重みを `weight[v]` に持ちます。

- どの 2 頂点 u, v についても、u-v の最小カットの値は、木の u-v の道の上の重みの最小に等しくなります。`min_cut(u, v)` はこの最小を返します。手間は木の高さに比例します。u と v が同じなら `Cap` の最大値を返します。
- 木の辺 (v, parent[v]) を切ったときの v の側の頂点集合 (v の部分木) について、元のグラフで端が両側に分かれる辺の容量の和は `weight[v]` に等しくなります。つまり、道の上の最小の辺で切った集合が、そのまま u-v の最小カットになります。
- `parent` は `HeavyLightDecomposition(par)` にそのまま渡せます。

使い方の例です。

- 2 頂点の最小カットを何度も答える問題 (洛谷 P4897) は、`min_cut(u, v)` を呼びます。
- 全組の最小カットの値の種類数 (LOJ 2042) は、`weight[1]` から `weight[n - 1]` の種類数です。どの組の値も、木のどこかの辺の重みになるためです。
- 最小カットが x 以下の組の数 (洛谷 P3329) は、木の辺を重みの大きい順に Union-Find でつなぎ、x より大きい辺でつながる組を全体から引いて数えます。

## 中身

Gusfield の方法で作ります。グラフを縮めずに、元のグラフで最大流を n - 1 回流します。根を 0 とし、全頂点の親を 0 にしておきます。頂点 s ごとに t = parent[s] として s-t の最小カット X (s ∈ X) を求め、辺 (s, t) の重みをその値にします。s 以外で X にあって親が t の頂点は、処理済みかどうかによらず親を s に付け替えます。t の親が X にあれば、s を t と t の親の間に入れます。後ろの未処理の頂点だけを付け替える簡単な形では、全組の値は合いますが、木の辺で切った集合が最小カットになるとは限りません。

頂点を処理する順は、どの順でも正しく作れます。ここでは、同じ親を持つ未処理の頂点が続くように選びます。

最大流は、網を 1 回だけ組み、flow ごとに変えた弧の容量だけを戻す push-relabel (highest label、gap、global relabel) の前流の段で流します。手を 2 つ足しています。

- 最初の高さに、元のグラフで t から測った距離を使います。s の弧を飽和させて s を高さ n に置くと、残りの残余の弧はどれも元のグラフにある弧なので、高さの付け方の条件を満たします。t からの BFS は途中で止めて状態を残し、s の隣に距離が付くところまでだけ進めます。カットが {s} のままなら t は同じ頂点が続くので、多くの flow で BFS を省けます。
- カットは、流量が s の重み付きの次数に等しければ {s}、t の次数に等しければ t 以外の全部、どちらでもなければ s の側の最小の集合にします。最後の場合だけ、余りを s へ戻してから s から BFS で求めます。

procon-judge の 4 問で書き比べました。x64-gcc の値です (アルゴリズムの時間、run 44269981947)。同じ回の、今の Library の MaxFlow (Dinic) で組ごとに網を作り直して Gusfield の方法を書いた形と比べています。
