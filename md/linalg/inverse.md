正方行列の逆行列を求めます。

```cpp
template <class T> std::optional<Matrix<T>> inverse(Matrix<T> A);
```

正則でなければ `std::nullopt` を返します。`T` は体で、`ZMod` なら法は素数でなければなりません。浮動小数点数では、列の中で絶対値が最大の値を要に選び、絶対値が $10^{-8}$ 以下なら 0 とみなします。$n \times n$ の行列に $O(n^3)$ の時間がかかります。

## 中身

$[A \mid I]$ を前進消去すると、要の行が $[T \mid Y]$ ($T$ は上三角で $YA = T$) になるので、$TX = Y$ を後退代入で解きます。`ZMod` の前進消去は `det` と同じ遅らせた更新です。

右半分の列は、「行 $r$ の単位行列の 1 の位置」として付け替えます。行を $t$ 番目の要にするとき、その行の 1 を位置 $t$ に移し、位置 $t$ にあった行の 1 を空いた位置に移します。その 2 つの位置には、まだ持ち主の行にしか値がありません。なので、この移し替えは右半分の列の入れ替えと同じです。すると要の行の右半分は位置 $t$ 以下にしか値がなく、残りの行の更新は、今の列から $n$ + (要の数) の手前までの列で済みます。前進消去の手間は $5n^3/6$ から $n^3/2$ に減ります。後退代入は `solve` と同じく、下から 8 行ずつの組にします。$n \le 16$ の `ZMod` とほかの体は、素朴な掃き出しにします。

法が奇数なら、前進消去の要を探す列、要の行、行ごとの掛ける数を AVX2 で 4 個ずつ求めます。形は `solve` と同じで、右半分の付け替えは要を探す左半分の列に触れません。要の行と要の値は本当の値の $2^{-32}$ 倍になりますが、$T$ の各行と $Y$ の行が同じ倍率なので、解は変わりません。行列と要の行は、Linux では huge page に置きます。

procon-judge の yosupo-inverse-matrix で書き比べた zmod_inv_relabel を写し、前進消去を zmod_inv_hpv の形にしました。zmod_inv_relabel は x64-gcc の Xeon 8573C で 21.56 ms と首位で、前の形 (zmod_inv_blk8t) の 28.61 ms から 25% 減っていました。この形の写し (lib-neo-runv) は、x64-gcc の 7 機種のうち 5 つで、行列を huge page に置いただけの前の lib-neo より 3〜8% 速くなりました。Xeon 6973P-C では 9% 遅く、6975P-C では並びました (run 42371441667 など)。6973P-C は行列式でも同じ形が遅くなった機種です。記録は algo-notes の notes/linear-algebra.md にあります。
